# LIP-0001 Catalog

This implementation is for one Catalog writer in an isolated development
metadata namespace. It replaces the old `serve`/TOML and schema/secret/user SQL
prototype. There is no migration, TLS, privilege enforcement, active-active
coordination, or failed-drop repair. Do not deploy it publicly.

## Initialize and start

Provision Oxia and its namespace first. See [the minimal manifest](../options/catalog.yaml).
Create a regular UTF-8 password file owned by the process UID, with mode `0600`
or `0400`. Its contents must be 1–1024 bytes, optionally followed by one newline.
Never put its contents or path in the manifest, command arguments as an inline
password, source control, or logs.

```sh
cargo run --locked -p lyra-catalog-cli -- init --manifest options/catalog.yaml --password-file /path/to/protected-password
cargo run --locked -p lyra-catalog-cli -- start --manifest options/catalog.yaml
psql -h 127.0.0.1 -p 5432 -U lyrasys -d public
```

`init` creates the numeric `lyrasys` user and stored `lyrasys`/`public` databases.
It stores only a SCRAM-SHA-256 verifier. Reinitialization fails without changing
credentials or inventory. An incomplete initialization fails closed with no
automatic resume. `start` never bootstraps or reads the password file.

The minimal manifest requires `metadata.oxia.endpoint`, `namespace`, and
`postgres.listen`. Optional `observability.otlp_endpoint` sends metrics/logs to
an OTLP/gRPC Collector. Optional `health.listen` exposes `/live` and `/ready`.
Unknown fields, invalid addresses, duplicate listeners, and manifests above
64 KiB are rejected. General settings and tracing configuration are not enabled.

## SQL and compatibility

Supported: `CREATE DATABASE` with owner/UTF8/connection controls, rename,
owner/control changes, `RESET ALL`, normal/forced drop, `SHOW DATABASES [LIKE]`,
and read-only SELECTs including `current_database()` and `pg_catalog.pg_database`.
`CREATE DATABASE IF NOT EXISTS` and `DROP ... WITH (FORCE, TIMEOUT '30s')` are
Lyra extensions. Timeout accepts positive integers in `ms`, `s`, or `min`.
The default is 30 seconds. Named SET/RESET, user/schema/secret/table DDL,
templates, and non-UTF8 encodings are explicitly unsupported.

All database DDL is rejected inside explicit transaction blocks. General SQL
transactions are not implemented. Introspection is a subset, not a complete
PostgreSQL catalog: numeric identities use BIGINT wire values rather than OID.
Only UTF8 and fixed C/POSIX-style comparison are supported. Catalog views never
expose password verifiers. SQL identifiers fold unquoted ASCII case and truncate
at a valid UTF8 boundary with a notice; startup identifiers are exact and bounded.

`public` can be renamed/dropped and is never recreated on restart. `lyrasys` is
protected from SQL connection/mutation. Ownership resolves an existing numeric
user; privileges and user-management SQL are deferred.

Name checks, mutations, and admission are serialized. Rename/drop inspect all
sessions in this Catalog, not only the issuing session. Connection-control changes
affect new sessions. Forced drop persists DROPPING, cancels target sockets, waits
for admission guards to drain, then deletes. Timeout/failure leaves DROP_FAILED;
restart makes an interrupted DROPPING terminal. There is no retry/repair command.
Unreconciled writes withdraw readiness until restart. Operations survive issuer
disconnect and receive a bounded graceful-shutdown drain.

The three persisted fields `allow_connections`, `connection_limit`, and `state`
are the minimum representation proposed for review of these agreed behaviors.

## Protocol and observability

SCRAM uses pinned rsasl 2.3.1, no trust/MD5/cleartext fallback. Startup/authentication
has a ten-second deadline; startup frames are limited to 16 KiB, other frames to
1 MiB, and SCRAM input to 4096 bytes. Text is validated before upstream decoding;
binary parameter bytes are not treated as UTF8. SSL/GSS requests receive refusal.

Catalog registers an empty ephemeral component presence through Meta and withdraws
readiness when its registration is unavailable. This does not provide writer fencing.
OpenTelemetry 0.31 exports the nine LIP metric families and sanitized structured
logs. JSON stdout remains available without a Collector; traces are disabled.
Metric labels are fixed operation/outcome/backend/component/reason categories.
Histograms use bounded second buckets from 1 ms to 60 s. Export timeout is two
seconds, metric interval five seconds, and log queues are bounded to 1024 records.
Exporter failures/recovery are rate-limited JSON events, excluded from their own
OTLP bridge. Do not also ingest stdout into the same log pipeline.

## Verification and image

```sh
cargo fmt --all --check
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
docker build -t mattison/lyra-catalog:lip-0001 .
kind load docker-image --name lyra-lip1 mattison/lyra-catalog:lip-0001
```

The Dockerfile builds from the locked Meta commit; it does not copy local secrets
or credentials. The runtime is non-root. See the separate charts and chaos PRs
for explicit kind deployment, init, fault tests, and Collector evidence.

Known upstream limitation: Oxia 0.17.1 can reuse a deleted-tail sequence ID.
Physical deletion is intentional; this implementation adds no tombstone or
allocator workaround and does not claim historical ID non-reuse.
